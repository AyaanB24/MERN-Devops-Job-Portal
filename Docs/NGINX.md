# Nginx Configuration Guide - MERN Job Portal

## What is Nginx?

Nginx is a high-performance, open-source web server and reverse proxy. In our MERN Job Portal, it serves as:

1. **Static file server** - Serves React build files (HTML, CSS, JS)
2. **Reverse proxy** - Forwards API requests to backend
3. **SPA router** - Handles client-side routing for React

---

## Why Nginx Instead of Node?

### Traditional Node.js Approach (❌ Inefficient)

```
Client → Node.js HTTP Server → Serve static files + handle API
```

**Problems:**
- Node blocks on I/O operations (serving files ties up the event loop)
- Single-threaded - can't fully utilize multi-core systems
- Memory overhead for every request
- Slower response times for static assets

### Nginx Approach (✅ Efficient)

```
Client → Nginx (static files) ─┐
                               ├─→ Node.js (API only)
                               ↓
                           Backend logic
```

**Benefits:**
- Nginx written in C - extremely fast (~1000+ req/sec)
- Multi-worker architecture uses all CPU cores
- Minimal memory footprint
- Specializes in file serving and routing
- Node.js focuses only on business logic (APIs)

**Performance:** Nginx 2-3x faster than Node for static files

## Dockerfile - Multi-Stage Build

**File:** `frontend/Dockerfile`

```dockerfile
# Stage 1: Build React Application
FROM node:22-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build  # Generates /app/dist

# Stage 2: Serve with Nginx
FROM nginx:alpine
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

### How It Works

1. **Stage 1 (Builder)**
   - Uses `node:22-alpine` image (~170MB)
   - Installs dependencies: `npm ci`
   - Builds React app: `npm run build`
   - Creates `/app/dist` with optimized bundles

2. **Stage 2 (Runtime)**
   - Uses `nginx:alpine` image (~50MB)
   - Discards builder stage and node_modules
   - Copies only `/app/dist` → `/usr/share/nginx/html`
   - Exposes port 80
   - Runs nginx server

### Size Optimization

```
Without multi-stage:
  node:22-alpine (170MB)
  + node_modules (300MB)
  + /dist (10MB)
  ──────────────────────
  = 480MB final image ❌

With multi-stage:
  nginx:alpine (50MB)
  + /dist (10MB)
  ───────────────────
  = 60MB final image ✅

Result: 8x smaller! 🎉
```

## Nginx Configuration

**File:** `frontend/nginx.conf`

```nginx
server {
    listen 80;
    server_name localhost;

    # Gzip compression
    gzip on;
    gzip_types text/plain text/css text/javascript application/javascript;
    gzip_min_length 1024;

    # Static assets with long-term caching
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        root /usr/share/nginx/html;
        expires 1y;
        add_header Cache-Control "public, immutable";
        try_files $uri =404;
    }

    # SPA routing: All other requests go to index.html
    location / {
        root /usr/share/nginx/html;
        try_files $uri $uri/ /index.html;
        add_header Cache-Control "no-cache";
    }

    # Health check endpoint
    location /health {
        access_log off;
        return 200 "healthy";
        add_header Content-Type text/plain;
    }

    # Security: Block hidden files
    location ~ /\. {
        deny all;
        access_log off;
    }
}
```

### Configuration Breakdown

#### 1. Gzip Compression

```nginx
gzip on;
gzip_types text/plain text/css text/javascript application/javascript;
gzip_min_length 1024;
```

**What it does:**
- Compresses responses before sending to client
- Reduces HTML/CSS/JS by 60-80%
- Only compresses if >1KB (smaller files not worth overhead)

**Example:**
- Uncompressed: 300KB
- Gzip compressed: 80KB → 73% reduction
- Browser automatically decompresses

#### 2. Static Asset Caching

```nginx
location ~* \.(js|css|png|jpg|...)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}
```

**Why 1 year?**
- React build creates unique filenames: `bundle.a1b2c3d4.js`
- If file changes → new filename generated
- Browser caches old file for 1 year
- New deploy → new filenames → browser gets new files

**Headers:**
- `expires 1y` - Browser won't request again for 1 year
- `public` - CDNs can cache this
- `immutable` - Content never changes (different filename if updated)

**Result:** Instant loads on repeat visits

#### 3. SPA Routing - The Magic

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

**The Problem:**
```
User visits /jobs
Browser requests GET /jobs
Without this rule:
  Nginx looks for file /jobs → Not found → 404 error
  React Router never loads
```

**The Solution:**
```
try_files $uri $uri/ /index.html

1. Try exact file: /jobs → doesn't exist
2. Try directory: /jobs/ → doesn't exist
3. Fallback: /index.html → found!

Browser loads index.html with all JS bundles
React Router reads URL (/jobs) from browser
React Router renders correct component
```

**Key insight:** All routes serve the same HTML file. Client-side routing handles navigation.

#### 4. Health Check Endpoint

```nginx
location /health {
    return 200 "healthy";
    add_header Content-Type text/plain;
}
```

**Used by:**
- Docker health checks
- Load balancers (to verify app is running)
- Monitoring systems

```bash
curl http://localhost/health
# Response: "healthy"
```

#### 5. Security - Block Hidden Files

```nginx
location ~ /\. {
    deny all;
}
```

**Prevents access to:**
- `.env` files
- `.git` directories
- `.htaccess` files
- Any hidden config files

## How Nginx Connects in Docker

### Inside Docker Container

```dockerfile
# Frontend container
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

**File locations in container:**
```
/etc/nginx/conf.d/default.conf  ← Our custom config
/usr/share/nginx/html/          ← React build output
                ├── index.html
                ├── assets/
                │   ├── bundle.abc123.js
                │   ├── styles.def456.css
                │   └── ...
                └── favicon.ico
```

### Docker Compose Setup

```yaml
services:
  frontend:
    build:
      context: ./frontend
      dockerfile: Dockerfile
    container_name: jobportal-frontend
    ports:
      - "80:80"      # Host port 80 → Container port 80
    depends_on:
      - backend
    networks:
      - jobportal-network
```

**Port mapping:** `80:80`
- First `80` = host machine port
- Second `80` = container port
- Access via: `http://localhost`

### Communication Flow

```
1. Browser requests: http://localhost/jobs
   ↓
2. Host OS directs to port 80 (nginx container)
   ↓
3. Nginx receives request for /jobs
   ↓
4. Nginx config: try_files $uri $uri/ /index.html
   ↓
5. Serves /index.html with all React bundles
   ↓
6. Browser loads React app
   ↓
7. React Router reads URL and renders /jobs component
   ↓
8. If component needs data:
   → API request to http://localhost:5000/api/...
   → Docker network routes to backend container
   → Backend processes request
   → Response sent back to frontend
```

## Performance Optimization

### 1. Compression

Before:
```
HTML: 50KB
CSS:  100KB
JS:   200KB
────────── 
Total: 350KB
```

After Gzip:
```
HTML: 15KB (70% reduction)
CSS:  25KB (75% reduction)
JS:   50KB (75% reduction)
────────── 
Total: 90KB ✅
```

Time saved: 350KB ÷ 5Mbps = 560ms → 90KB ÷ 5Mbps = 144ms (416ms saved!)

### 2. Browser Caching

First visit:
```
Download all assets: ~500ms
```

Repeat visit (1 year):
```
All files in cache: ~0ms (instant!)
```

### 3. CDN Integration (Production)

```nginx
add_header Cache-Control "public, immutable";
```

This header allows CDNs (CloudFlare, AWS CloudFront) to cache files globally:
```
USA user:  nginx (EU) → CDN (USA) → User (50ms instead of 200ms)
Asia user: nginx (EU) → CDN (Asia) → User (20ms instead of 500ms)
```

## Issues We Faced

### Issue 1: SPA Routes Returning 404

**Symptom:**
```
Click /login → 404 error page
```

**Root cause:**
```nginx
# ❌ WRONG - No SPA routing
location / {
    root /usr/share/nginx/html;
}
```

**Solution:**
```nginx
# ✅ CORRECT - SPA routing
location / {
    try_files $uri $uri/ /index.html;
}
```

---

### Issue 2: Static Assets Not Cached

**Symptom:**
```
Reload page → all assets re-download (slow)
```

**Root cause:**
```nginx
# ❌ WRONG - No cache headers
location ~* \.(js|css)$ {
    # Missing cache headers
}
```

**Solution:**
```nginx
# ✅ CORRECT - Cache headers added
location ~* \.(js|css)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}
```

---

### Issue 3: API Requests to Backend

**Symptom:**
```
API calls fail with 404
```

**Root cause:**
```javascript
// ❌ WRONG - No port specified
axios.get('/api/auth/profile')
// Goes to localhost:80 (nginx) not localhost:5000 (backend)
```

**Solution:**
```javascript
// ✅ CORRECT - Full URL with port
axios.get('http://localhost:5000/api/auth/profile')
```

## Interview Key Points

1. **Why Nginx over Node.js?**
   - Written in C (faster than JavaScript)
   - Multi-worker architecture (uses all CPU cores)
   - Optimized for static file serving
   - Node.js focuses on API logic only

2. **Multi-stage Docker builds**
   - Build stage with Node.js (~170MB)
   - Runtime stage with Nginx (~50MB)
   - Result: 60MB final image (vs 480MB without multi-stage)

3. **SPA Routing**
   - React app is a single HTML file
   - All routes serve same HTML
   - React Router handles client-side navigation
   - Nginx must fallback to index.html for non-existent paths

4. **Caching Strategy**
   - Hashed filenames: `bundle.a1b2c3d4.js`
   - Cache assets for 1 year
   - When code changes → new hash → new filename
   - Browsers automatically get new version

5. **Compression**
   - Gzip reduces assets by 70-80%
   - Saves 300ms+ on first load
   - Browser automatically decompresses

6. **Port Mapping in Docker**
   - Frontend on port 80 (user-facing)
   - Backend on port 5000 (internal)
   - API calls use full URL: `localhost:5000/api/...`

7. **Security Considerations**
   - Block hidden files (`.env`, `.git`)
   - Set proper cache headers
   - Use HTTPS in production

## Troubleshooting

| Issue | Cause | Solution |
|-------|-------|----------|
| Routes return 404 | Missing SPA routing | Add `try_files $uri $uri/ /index.html` |
| Assets not caching | Missing cache headers | Add `expires 1y` and `Cache-Control` |
| Slow first load | No compression | Enable `gzip on` |
| API requests fail | Wrong URL/port | Use `http://localhost:5000/api/...` |
| Can't connect | Container not running | Check `docker ps` |
| Health check fails | Wrong endpoint | Verify `/health` returns 200 |

## Production Considerations

1. **HTTPS**
   ```nginx
   listen 443 ssl http2;
   ssl_certificate /etc/ssl/certs/cert.pem;
   ssl_certificate_key /etc/ssl/private/key.pem;
   ```

2. **Redirect HTTP to HTTPS**
   ```nginx
   server {
       listen 80;
       return 301 https://$server_name$request_uri;
   }
   ```

3. **Security Headers**
   ```nginx
   add_header X-Frame-Options "SAMEORIGIN";
   add_header X-Content-Type-Options "nosniff";
   add_header X-XSS-Protection "1; mode=block";
   ```

4. **Rate Limiting**
   ```nginx
   limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;
   limit_req zone=api burst=20;
   ```
