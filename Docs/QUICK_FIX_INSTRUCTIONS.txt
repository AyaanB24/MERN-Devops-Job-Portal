================================================================================
                    KEY CLARIFICATION
================================================================================

WHY DO CANDIDATES SEE ALL JOBS?
  This is INTENTIONAL and CORRECT!
  
  Role-based job visibility:
  ✅ Candidates: See ALL jobs (need to browse)
  ✅ Recruiters: See ONLY their jobs (in "Manage Jobs")
  ✅ Admins: See all jobs (admin panel)

HOW IS RECRUITER ISOLATION WORKING?
  Look at the routes:
  
  /api/jobs (GET) - PUBLIC
    └─ Candidates use this to browse ALL jobs
    └─ Recruiters can use this, but getJobs filters by company owner
    └─ Result: Recruiters see only their jobs
  
  /api/jobs/:id (GET) - PROTECTED with "protect"
    └─ Requires authentication
    └─ Checks company ownership
    └─ Recruiters can only access own jobs
    └─ Result: 403 Forbidden for other recruiter's jobs

WHY IS DELETE RETURNING 403?
  This is CORRECT and SECURE!
  
  If delete returns 403, it means:
  ✅ Authorization check is working
  ✅ Recruiter cannot delete other's jobs
  ✅ Recruiter isolation is PROTECTING the data
  
  Test this is working:
  - Login as Recruiter A
  - Delete Recruiter A's job: ✅ Should work (200 OK)
  - Login as Recruiter B
  - Try to delete Recruiter A's job: ✅ Should return 403
  
  If you get 403 on your own job, the company owner might not be set correctly
  in the database. Check MongoDB.
